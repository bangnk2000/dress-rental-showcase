# Workspace Structure — pnpm Monorepo, Two Apps, One Contract

## 1. The Tree

```
<product>/
├── pnpm-workspace.yaml             # packages: apps/*, packages/*
├── package.json                    # root: orchestration scripts ONLY — no runtime deps
├── .nvmrc                          # 22  (floor is 22.18 — see §3)
├── .gitignore                      # node_modules, dist, .env*, coverage, playwright-report
├── init.sh                         # root harness resume-verification (04)
├── AGENTS.md                       # root harness brief (04) — the ONE harness in this repo
├── feature_list.json               # root, spans both apps (04 UNIT_OF_WORK)
├── packages/
│   └── contract/
│       ├── openapi.json            # GENERATED by apps/be, committed, never hand-edited
│       └── README.md               # ownership rules (3 lines: who writes, who reads, how)
├── apps/
│   ├── be/                         # init-nestjs-hexagonal layout, unchanged inside
│   │   └── scripts/emit-openapi.ts # the ONE addition this set makes to the BE (02 §2)
│   └── fe/                         # init-react layout, unchanged inside
├── docs/spec/                      # this set + init-nestjs-hexagonal + init-react + init-harness
└── .github/workflows/ci.yml        # drift gates + per-app gates (03)
```

Both apps keep their own `package.json`, tsconfig, lint config, and test setup — the stack sets
already specify those. The workspace adds **coordination**, not a shared build system: no Nx/
Turbo until the repo demonstrably needs task caching (YAGNI; record the upgrade as a decision
in `AGENTS.md` if taken).

## 2. Root `package.json` — orchestration scripts

Package names MUST be `be` and `fe` (each app's `package.json` `name` field) — every root
script and CI line filters by these names.

```jsonc
{
  "name": "<product>",
  "private": true,
  "engines": { "node": ">=22.18" },
  "scripts": {
    "openapi:emit":   "pnpm --filter be openapi:emit",
    "generate:api":   "pnpm --filter fe generate:api",
    "contract":       "pnpm openapi:emit && pnpm generate:api",
    "contract:check": "pnpm contract && git diff --exit-code packages/contract apps/fe/src/api/generated",
    "check":          "pnpm --filter be build && pnpm --filter fe check",
    "lint":           "pnpm -r --if-present lint",
    "arch":           "pnpm -r --if-present arch",
    "test":           "pnpm -r --if-present test",
    "build":          "pnpm -r --if-present build"
  }
}
```

- `contract` is the developer's one command after any BE API change.
- `contract:check` is the same thing as a GATE — regenerate everything, fail on any diff. It is
  the first gate in CI and in `init.sh` because it is the monorepo's reason to exist.
- Root has **no dependencies**. Orval lives in `fe`, Nest CLI in `be`; the root only sequences.

## 3. Version Floors (union of both sets)

| Constraint | Source |
| --- | --- |
| Node **≥ 22.18** (pin 22 LTS in `.nvmrc`) | Orval 8 floor (init-react 04) — also satisfies Nest 11 and Vite 8 |
| pnpm 10.x, pinned via `packageManager` at bootstrap time | one lockfile at root; `pnpm install --frozen-lockfile` everywhere |
| TypeScript per each stack set | apps do NOT need the same TS version — each app compiles itself |

## 4. Deltas vs the Stack Sets' Defaults (these win inside this repo)

Each stack set was written repo-per-app; five of its defaults change here. Everything not
listed is unchanged.

| # | Stack-set default | Monorepo delta |
| --- | --- | --- |
| 1 | init-react 04 §1: `openapi.json` committed **in the FE repo root**, Orval `input: './openapi.json'` | Contract lives in `packages/contract/openapi.json`; `orval.config.ts` sets `input: '../../packages/contract/openapi.json'` |
| 2 | init-react 04 §7: backend drift handled by **artifact/curl sync step** reviewed as a PR | DELETED — there is no sync step. The BE emit writes the file directly; same-PR atomicity replaces the sync review |
| 3 | init-nestjs 06 §9: Swagger served at `/docs` from the running app | Kept, PLUS the offline `scripts/emit-openapi.ts` + `openapi:emit` script (02 §2) — serving and emitting are separate paths |
| 4 | Both sets' `13-harness-engineering.md`: one binding **per repo** | Neither is instantiated; the merged root binding (04) replaces both |
| 5 | init-react 05/mutator: `VITE_API_BASE_URL` points at a separate API origin | Prod = same origin (`''`, API under `/api`) because FE and BE ship together (03 §3); dev = `http://localhost:3000` or a Vite proxy |

## 4b. Adding Another Client App (a second SPA, or a Next.js site per `init-nextjs`)

The contract stays single-source; every client is one more generated consumer. Adding one is a
fixed checklist — skipping any line leaves a client the drift gates cannot see:

1. `apps/<name>/package.json` with a stable `name` (root scripts filter by it) and the same
   gate script names as the other apps: `check`, `lint`, `arch`, `test`, `build`, `generate:api`.
2. Root `package.json`: append `pnpm --filter <name> generate:api` to `generate:api`, its
   `src/api/generated` to the `contract:check` diff, and `pnpm --filter <name> check` to `check`.
3. `init.sh`, CI (the contract job's diff + an app job + the change-scope filter, with
   `packages/contract/` as an input) — same three edits.
4. An app-level `apps/<name>/AGENTS.md` = architecture contract only (commands, rules,
   §Deviations). The harness stays at the root: no `CLAUDE.md`, `feature_list.json`, `init.sh`
   or handoff inside the app — the stack set's `13-harness-engineering.md` is reference only (§4 #4).
5. Root `AGENTS.md` names the stack set authoritative inside the new app; `docs/spec/` vendors it.
6. The app's bootstrap is ONE ledger entry (e.g. `infra/<name>-bootstrap`) with the new app's
   gates + runtime proof as evidence.

Next.js-specific deltas (`init-nextjs` defaults that change here, on top of §4 #1/#2/#4):

| # | init-nextjs default | Monorepo delta |
| --- | --- | --- |
| N1 | 04 §1/§8: `openapi.json` at the app root; freshness diff covers `openapi.json` | `input: '../../packages/contract/openapi.json'`; the app diffs only its `src/api/generated` (the contract diff is the root's) |
| N2 | 04 §1: rewrite `/api/be/:path*` → `${API_URL}/:path*` | If the emitted paths already carry the BE's global prefix (`/api/v1/...`), rewrite THAT prefix 1:1 (`/api/v1/:path*` → `${API_URL}/api/v1/:path*`) and let the server-side mutator base be `API_URL` — no second prefix to strip |
| N3 | 13 §4 `init.sh` + harness-file presence check; 08 §2 `CLAUDE.md` per app | Neither — root harness only (item 4 above) |
| N4 | Dev port 3000 | The NestJS BE owns 3000; give the Next app its own (`next dev --port <n>`) and record it in the app's `AGENTS.md` |
| N5 | "FE and BE ship as one unit" means one static artifact behind the BE's origin (03 §3) | A Next app is its own Node process. Same-origin for the browser still holds via N2's rewrite; the release lane must list the extra process + its reverse-proxy route |

## 5. Smells

- A second lockfile (`apps/*/pnpm-lock.yaml`) — the workspace has exactly one, at root.
- Root `package.json` growing dependencies, or an app importing another app's code directly.
  Cross-app sharing happens ONLY through `packages/contract` (and future `packages/*` extracted
  deliberately, as a recorded decision).
- `--filter` by path (`./apps/be`) in one script and by name (`be`) in another — pick names,
  everywhere.
- An Nx/Turbo config appearing without a decision record in `AGENTS.md`.
- `docs/spec/` copied but the app bootstraps improvising against it — the spec folders are the
  authority; deltas live only in §4 above.
